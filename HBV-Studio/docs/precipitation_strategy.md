# 降水方案说明

## 推荐优先级

### 1. `grid_only`
- 含义：直接使用 `1 km` 格点降水。
- 用途：快速建立基线结果。
- 优点：最简单，最适合作为第一版。
- 适用阶段：所有对象的首轮试运行。

### 2. `grid_plus_station_bias`
- 含义：以 `1 km` 格点降水为主，再用站点做偏差订正。
- 用途：正式方案优先推荐。
- 优点：
  - 保留格点的空间分布
  - 同时吸收站点实测信息
- 适用阶段：对象一和对象二的正式结果版本。

### 3. `thiessen_station_only`
- 含义：只用站点，通过泰森多边形把降水分配到流域。
- 用途：快速对比方案或数据缺失时的临时替代。
- 风险：
  - 会丢失格点降水的空间细节
  - 对山地流域通常不是最终优选方案
- 建议：只作为基线对照，不建议直接作为最终成果。

- `grid_plus_station_bias`：新工作区使用 `occurrence_amount_v2`。发生订正与湿日定量分开；可靠的全站无雨证据允许严格归零，湿日倍率下限不再抬高无雨日；订正后执行同像元、同月守恒与过度再分配阻断。
- `thiessen_station_only`：已实现 `v1` 基线脚本，按最近站点分配降水到流域栅格。

旧配置未声明算法版本时按 legacy v1 回放，避免历史结果被无提示改写。新建正式方案须冻结阈值、置信度和倍率范围后再率定，不得根据出口 NSE 反调降水订正规则。

## 当前建议

1. 保留原始格点场，用 `grid_only` 生成可复核基线。
2. 对站点日期、单位、坐标、缺测和复制序列做完整性检查。
3. 冻结 `occurrence_amount_v2` 规则后生成订正场，并比较原场、订正场和逐站留一诊断。
4. 订正 QC 未阻断后才进入日尺度模型；小时强迫只继承验收后的日总量。
5. `thiessen_station_only` 只用于对比，不作为默认正式方案。
