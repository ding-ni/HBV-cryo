# HBV-Cryo

HBV-Cryo 是面向寒区流域的分布式 HBV 水文模拟与率定系统。工程包含模型计算内核、数据准备脚本和 HBV-Studio 图形化工作流，可用于日尺度或可配置时间步长下的流域径流模拟、参数率定、结果诊断与过程组分分析。

## 工程结构

- `HBV-Cryo/`：模型主干、率定入口、目标函数与结果输出逻辑。
- `HBV-Studio/`：图形化工作流、后端服务、前端界面与任务调度。
- `数据准备/`：地理数据、气象数据、观测径流等输入准备脚本。
- `配置/`：流域配置模板与小型示例配置。
- `公共/`：跨流程复用的公共函数与内部实现。
- `dev_tools/`：开发验证辅助工具，不作为常规建模入口。

## 模型能力

- 分布式栅格化 HBV 产流计算。
- 降雨、降雪、融雪和冰川融水过程组分追踪。
- 单阈值两分区 `CFMAX` 融雪/融冰参数结构。
- 土壤含水、上层线性水库、下层线性水库与马斯京根汇流。
- 可选冰川模块和上游边界入流模块。
- 支持默认日尺度计算，并保留可配置时间步长接口。
- 支持 Monte Carlo、差分进化及局部细化等率定流程。

## 基本使用

1. 基于 `配置/流域配置模板.json` 创建流域配置，或在 HBV-Studio 中新建工程。
2. 准备流域边界、DEM、观测径流、降水、气温和潜在蒸散发等输入数据。
3. 使用图形化工作流运行：

   ```powershell
   python HBV-Studio/launch.py
   ```

4. 或使用模型脚本入口运行：

   ```powershell
   python HBV-Cryo/01_训练率定.py
   ```

## 开发检查门禁

前后端重构、界面专业化和打包相关修改，在提交前至少运行：

```powershell
python dev_tools/studio_baseline_check.py
```

该检查会覆盖 Python 语法、前端 JavaScript 语法、`studio_service.py` API 路由快照、源码 / Demo / 安装包关键路径，以及源码启动链 `/api/health`。如果有意新增、删除或改名 API 路由，先人工确认兼容性，再更新快照：

```powershell
python dev_tools/studio_baseline_check.py --update-api-snapshot
```

`pytest` 可用时，再补充运行：

```powershell
python -m pytest HBV-Studio/tests
```

涉及界面视觉、布局或前端交互的修改，还应启动本地服务后运行 Playwright 视觉烟测：

```powershell
python dev_tools/studio_visual_smoke.py --url http://127.0.0.1:8765/
```

涉及空间预览或 GIS 薄接口的修改，还应在本地服务运行时检查示例工作区至少能返回三类空间图层：

```powershell
python dev_tools/studio_geo_smoke.py --url http://127.0.0.1:8765/
```

## 数据输入说明

- 流域边界通常使用矢量数据，DEM 使用栅格数据；冰川边界为可选输入。
- 观测径流可使用 CSV 或 Excel 文件，需包含日期和流量字段，具体字段名由工作流配置或导入步骤解析。
- 降水、气温和潜在蒸散发可使用本地格点数据，也可通过已接入的数据源流程准备。
- ERA5 降水、气温和潜在蒸散发流程在配置满足条件时可用于自动准备输入。累计型 `tp`、`ssrd`（以及兼容旧流程的 `total_evaporation`）按“次日 00:00 对应前一日总量”结算；最后一年缺少次年 `01-01 00:00` 收尾样本时拒绝生成，不再用当年 `12-31 18:00` 代替完整日量。
- MSWEP 和 CMFD 当前按本地已有数据源处理；若需要自动下载，应在数据源接口层单独扩展。
- 模型不强制固定空间分辨率，实际分辨率以 DEM、流域掩膜和气象输入对齐结果为准。

## 正式运行输入契约

- 日降水产品必须明确单位与日界。配置中若将 `降水产品元数据.formal_run_allowed` 标记为 `false`，Studio 与命令行率定都会拒绝正式运行。
- 本地日降水导入时，降水按面积平均重投影；气温和 PET 按双线性重投影；三者最终必须严格继承 DEM 活动流域掩膜。
- `grid_plus_station_bias` 默认使用 `occurrence_amount_v2`：干湿发生与湿日定量分开订正，全站可靠无雨时允许严格为 0，不再用定量倍率下限抬高无雨日。
- 发生订正后按同像元、同自然月守恒。高置信证据判定整月无雨时保持全月为干，不为守恒凭空恢复雨日；未分配水量必须显式报告。月内再分配倍率超过 2、移除比例超过 30% 或仍有未分配水量时，结果标记 `qc_blocked` 并禁止正式率定。
- 区间入流项目要求“预热末 14 日 + 率定期 + 验证期”边界资料 100% 完整。更早预热段可缺测并记录，但不能用这种豁免覆盖正式评价期。
- 日尺度出口 NSE/KGE 只表述为出口总流量拟合。区间本地产流需要结合上游路由残差、负残差体积、洪量误差和时滞诊断解释；区间目标约束默认关闭。
- 短资料运行须执行干/湿初始状态敏感性。末 14 日本地产流差超过 5% 或预热末总库容差超过 10% 时，结果只能作内部诊断；优先补充至少 1--2 个完整水文年的连续预热强迫，不能靠放宽参数边界消除初值差异。
- 连续历史预热使用 `historical_spinup_runner.py`，输出 `hbv_cryo_historical_spinup_forcing_manifest_v1` 和 `hbv_cryo_continuous_historical_spinup_sensitivity_v1`。预热收敛只解除初始状态门禁；产品日界、历史降水偏差过渡、站点完整性和区间水源筛查仍独立判定。

## 内核记账约定

- 上层水库 `q0 + q1 > UZ` 时按原始 `q0:q1` 比例缩放到可用库容，不使用固定 0.67/0.33 硬切。
- 土壤库超过 `FC` 的水按当步雨/雪/冰入渗比例转入 UZ，不再由 `min(SM, FC)` 静默截掉；雪库不使用会丢水的固定上限截断。
- 雪垫液态水分别维护 `WC_rain`、`WC_snow`、`WC_ice`，冻结、溢出和进入土壤的水量均按来源闭合；三者之和始终等于总 `WC`。
- 状态快照使用 `per_cell_branch_states_v2`。v1 快照可恢复总水量，但历史 WC 来源不可恢复，不能用于正式分源解释。
- 每次完整运行输出 `model_water_balance_summary.json`，记录逐时步最大闭合误差、低/高高程带累计误差、P/PET/AET/冰融/径流深、参数顶边和区间水源筛查。水量闭合、区间水源与初值收敛任一未通过，`scientific_acceptance.formal_result_accepted=false`。

## Git 数据边界

本仓库用于保存源码、配置模板、小型示例和必要文档。以下内容不应提交到 Git：

- 用户运行目录、运行结果、缓存和日志。
- 原始或派生的大体量水文、气象、GIS、遥感数据。
- 本机绝对路径、个人工作区配置、临时验收记录。
- 安装包、压缩包、打包中间目录和可执行构建产物。

需要共享的大文件或正式安装包应通过独立发布渠道、对象存储或交付目录管理，而不是直接放入源码仓库。
